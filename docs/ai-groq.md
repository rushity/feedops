# AI Article Analysis via Groq — Owner: Rushit (service owned by Rushik)

Article summarization/categorization calls Groq's OpenAI-compatible API.
Without a key, everything keeps working on the offline fallback.

## Setup (developer machine or deployment)

1. Obtain a Groq API key from the official console: https://console.groq.com/keys
2. In the local ignored `.env` (never committed) or deployment secrets, set:
   `GROQ_API_KEY=<key>`.
3. Optionally set `GROQ_MODEL` (default below). Restart the app.
4. Open any article with `?analyze=1` (e.g. `/articles/1?analyze=1`).
   The page states "Generated by remote AI" on success or
   "Offline analysis (AI API not used)" on fallback — it never pretends
   a live call succeeded.

## Environment contract

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `GROQ_API_KEY` | yes (for live AI) | — | Groq secret. Also read from `FEEDOPS_AI_API_KEY` / `OPENAI_API_KEY` (legacy). |
| `GROQ_MODEL` | no | `llama-3.3-70b-versatile` | Model ID. Also read from `FEEDOPS_AI_MODEL` (legacy). |
| `GROQ_BASE_URL` | no | `https://api.groq.com/openai/v1` | Endpoint override. `FEEDOPS_AI_BASE_URL` also honoured. |
| `GROQ_TIMEOUT` | no | `15` (s) | Request timeout. Falls back to `FEEDOPS_AI_TIMEOUT`. |
| `FEEDOPS_AI_ENABLED` | no | `true` | Set `false` to force offline fallback. |

## Model selection evidence

Default `llama-3.3-70b-versatile` was taken from Groq's official
Supported Models listing (https://console.groq.com/docs/models,
Production models table): 280 tok/s, 131k context, OpenAI-compatible
endpoint `https://api.groq.com/openai/v1/models`. Groq's free-tier
availability and rate limits can change — if calls start failing with
model errors, pick another current Production ID from that page and set
`GROQ_MODEL`. No live Groq call was made during implementation; live
behaviour is covered by mocked tests plus the manual `?analyze=1` check.

## Behaviour notes

- Requests send only the article title/summary (truncated) and the JSON
  contract prompt. No secrets, config, or unrelated DB content is sent.
- `response_format: {"type": "json_object"}` is requested; malformed or
  invalid model output is validated/clamped (`validate_analysis`) and the
  route degrades to the offline fallback instead of crashing.
- HTTP 429 → "rate limit" fallback; 401/403 → "authentication" fallback;
  timeouts/network errors → fallback. The API key never appears in logs
  or error strings (it travels only in the Authorization header).
- `summarize`, `categorize`, `analyze_article`, `is_ai_available`,
  and `validate_analysis` signatures are unchanged; `analyze_article`
  results keep the same keys, with `provider` now `"groq"` for live
  Groq results (custom endpoints still report `"remote"`).
- No database migration: analysis is computed on demand and displayed
  only, per the shared-schema contract.
